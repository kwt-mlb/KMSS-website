# Yearly handover checklist

Committees change. Websites die when nobody knows the password. Work through this
list on the day you hand over, not the week after.

## 1. Access (do this first)

- [ ] Add the new President and Media Lead as **repository admins**
      (GitHub → Settings → Collaborators and teams → Add people).
- [ ] Remove graduating members who no longer need access.
- [ ] Make sure **at least two people** have admin — never one.
- [ ] Hand over the **Sellfy** login and the bank account it pays into.
- [ ] Hand over the Instagram, the WhatsApp group admin rights, and the
      `hello@kmss.org.au` inbox.

> Everything on the website itself is public and version-controlled. The only real
> secrets are Sellfy, the email inbox and the socials.

## 2. Update the site for the new year

- [ ] `data/team.json` — replace the committee, update `"year"`.
- [ ] `data/site.json` — update `stats` (member count, events run).
- [ ] `data/events.json` — add the year's first events. Old ones archive themselves.
- [ ] `data/guide.json` — check every price and rule. Rent, phone plans, visa work
      hours and OSHC providers all change. **An out-of-date guide is worse than none.**
- [ ] `data/site.json` — refresh the `sponsors` list.

## 3. Show the next person

- [ ] Walk them through `docs/HOW-TO-EDIT.md` once, in person, while they add a
      real event themselves. Fifteen minutes now saves the site.
- [ ] Show them the red ✗ / green ✓ that appears after saving a file.
- [ ] Show them Commits → Revert, so they know nothing can be permanently broken.

## 4. Twice a year

- [ ] Read the Melbourne Guide end to end and fix what's changed.
- [ ] Click every external link (Sellfy, Cultural Office, PTV, WhatsApp invite).
      WhatsApp invite links expire — this one breaks most often.
- [ ] Check the site on a phone, not just a laptop.
